# บล็อค ERDDAP™ การร้องขอจากเนื้อหาของการร้องขอ, ไม่ได้ขึ้นอยู่กับ IP

เนื้อหานี้ขึ้นอยู่กับ [ข้อความจากรอย เมนเดลสัน ERDDAP™ กลุ่มผู้ใช้](https://groups.google.com/g/erddap/c/XcvPkoGtchg) .

## ปัญหา

ถ้าคุณเป็นเหมือนเรา คุณจะเห็นหุ่นจํานวนมาก ทําการขอข้อมูลของคุณ ERDDAP™ และบ่อยครั้งที่คําร้องขอดูเหมือน พวกเขาจะทําโดยอักษรรหัสไม่ดี ไม่ว่าจะเป็นโดย LLM (ฉันเดาว่า) หรือโดยมนุษย์ สิ่ง หนึ่ง ที่ เกี่ยว ข้อง กับ แอล แอล เอ็ม คือ พวก เขา จะ ทํา ตาม ที่ คุณ สั่ง ให้ พวก เขา ทํา ดัง นั้น ถ้า คุณ ไม่ บอก พวก เขา ให้ มี รหัส การ ส่ง กลับ บท และ อย่า บอก พวก เขา ว่า จะ ทํา อะไร ใน กรณี ที่ ต่าง กัน ตาม ปกติ รหัส จะ ไม่ ทํา อย่าง นั้น ทั้ง สอง อย่าง. และถ้าคุณบอกให้พยายามต่อไป มันจะทํา นั่นคือสิ่งที่เราได้เห็นอย่างน้อย

แต่คนที่คิดเลขใน ERDDAP™ แบบนี้:

 https://coastwatch.pfeg.noaa.gov/erddap/jplMURSST41.parquetWMeta
 

พวกเขาส่ง ERDDAP™ เข้าสู่ดินแดนไม่เคยกําหนด เนื่องจากที่ดีที่สุดที่ฉันสามารถหา ที่อยู่ URL นี้ไม่ได้เป็นเพียง ต้องการชุดข้อมูลทั้งหมด เลวร้ายยิ่งกว่าที่ร้องขอมา จากการเคลื่อนย้าย IP ดังนั้นการปิดกั้น IPs จะเลวร้ายยิ่งกว่า crack-mol คุณจะไม่ได้รับพวกเขาทั้งหมดบล็อก

ดังนั้นคําถามก็คือ คุณจะปิดกั้นจากเนื้อหาของคําขอได้อย่างไร ก่อนจะไปไกลกว่านี้ ถ้าคุณประสบอุบัติเหตุ อาจมาจากสาเหตุอื่น ๆ แล้วสิ่งที่เราเห็น ผมใช้เวลาส่วนใหญ่ ผ่านบันทึก ดัง นั้น จง ค้นคว้า เรื่อง นี้ ก่อน ลง มือ ทํา อะไร ๆ แต่ นี่ อาจ ทํา ให้ คุณ มี แนว คิด บาง อย่าง ที่ จะ ขัด ขวาง คํา ขอ เหล่า นี้.

เพื่อให้ชัดเจน, คุณคิดถึง ERDDAP™ ร้องขอเป็น:

 https://baseURL/erddap/method/datasetID.filetype?constraint
 

ในกรณีของเรา ตัวส่วนร่วมของอุบัติเหตุนั้น เป็นตารางรวม หรือตารางที่ร้องขอ ด้วยแฟ้มบางประเภท แต่ไม่มีข้อจํากัด ดังนั้นคําถามคือ จะยับยั้งคําขอโดยไม่มีเงื่อนไขได้อย่างไร นอก เสีย จาก ว่า ไม่ ง่าย อย่าง นั้น เพราะ มี ไฟล์ ประเภท ใด ๆ ที่ ไม่ จําเป็น ต้อง มี ข้อ จํากัด และ มี การ ปรับ ปรุง อย่าง ดี เรา จึง ไม่ ต้องการ ขัด ขวาง. หลังจากที่คุยกับคริสแล้ว และไม่ต้องสงสัยเลยว่าฉันได้ทิ้งบางอย่างไว้ ไฟล์ประเภทที่ประพฤติตัวดีโดยไม่มีเงื่อนไขคือ

## วิธี แก้

คําตอบ "ผมพบ" ได้ผลใน Apache2, ผมไม่รู้ nginx แต่ผมนึกว่ามันเหมือนกัน ตอน แรก ผม พยายาม ทํา ให้ ความ มั่นคง ปลอด ภัย เกิด ขึ้น แต่ ก็ ยุ่ง ยาก เกิน ไป และ ทํา งาน ไม่ ค่อย ได้. คําตอบคือให้ใช้ mod_ red ตอนนี้ผมเป็นอะไรก็ได้นอกจากผู้เชี่ยวชาญในเรื่องนี้ ดังนั้น ขณะที่ผมนิยามสิ่งที่ผมพยายามแก้ไข Ai. แชตจีพีทีจะให้คําตอบกับคุณ

ขั้นที่ 1 ให้ตรวจสอบว่าได้ติดตั้ง mod_ resendor แล้ว เนื่องจากวิธีการทําความแตกต่างนี้กับ OS นี่คือสิ่งที่คุณสามารถถามแชทบอทที่คุณชื่นชอบ

ขั้นที่ 2. ในแฟ้มที่เหมาะสมที่ปรับแต่ง sl สําหรับ Apache2 (ซึ่งแตกต่างอีกครั้งโดย OS) ยกตัวอย่างเช่น /etc/aptace2/site-sensable/sl.conf. เพิ่มคําจํากัดความที่เหมาะสม (หมายเหตุถ้าคุณคัดลอกนี้มีเพียง 4 บรรทัดที่สามอาจจะห่อ, ถอด) 

```
RewriteEngine On
RewriteCond %{QUERY_STRING} ^$
RewriteCond %{REQUEST_URI} ^/erddap/(griddap|tabledap)/[^/?]+\\.(?!(?:croissant|iso19115_2|iso19139_2007|iso19115_3_2016|ncCFHeader|ncCFMAHeader|das|dds|html|graph|subset|ncHeader|help|fgdc|iso19115|ncoJsonHeader)$)[A-Za-z0-9_]+$
RewriteRule ^ - [R=429,L]
```

ขั้นที่ 3 โปรดตรวจสอบว่าการปรับแต่งใช้ได้หรือไม่: `ปรับแต่งค่า sudo aspache2ctl` 

ขั้นตอน 4. เริ่ม appachage2: `sudo Systemctl. เริ่มการทํางาน abpache2 ใหม่` 

ขั้นที่ 5 Check logs ของคุณที่ไม่มีอะไรถูกบล็อกที่ไม่ควร และการร้องขอที่เหมาะสมโดยไม่ต้องเงื่อนไขการกลับมา 429 โดยไม่ต้องกด tomcat ของคุณ

## คําอธิบาย

ทําไมงานนี้และสิ่งนี้ไม่ -- นี่คือคําอธิบายจาก Claude.ai:

สาย 1 — `เขียนเครื่องใหม่ เปิด` 
เปิดการทํางานแบบ Mod_ regress สําหรับขอบเขตนี้ หากปราศจากมัน การเขียนคําสั่งใหม่/เขียนใหม่ จะเป็นการเพิกเฉย

สาย 2 — `เขียนใหม่ % &#123;kre_BAR_STRING&#125; ^$` 
สภาพ ที่ ต้อง เป็น จริง ก่อน ที่ กฎ ข้าง ล่าง จะ นํา มา ใช้ ได้. `% &#123;กําหนด&#125;` เป็นทุกอย่างหลังจาก? ในที่อยู่ URL ที่ร้องขอ ^$ คือ Regegex หมายถึง "เริ่มต้นของสตริงทันทีตามด้วยปลายสตริง" — เช่น สายเปล่า เงื่อนไขนี้เป็นจริงเฉพาะเมื่อไม่มีข้อความถามเลย -- ไม่มีการแสดงออกแบบสับปะรด/ต่อเนื่องตามคําขอ

สาย 3 — `เขียนใหม่ % &#123;rent_URI] ^/irdap/ (ตารางกริด |  tabledap ) + / (? &#33; (?) $) [A-Za-z0-9_]+$` 
เงื่อนไขที่สอง การตรวจสอบกับ `% &#123;1&#125;` -เส้นทางที่ลูกค้าขอมา เป็นเส้นทางที่เต็มรูปแบบเสมอ ไม่คํานึงถึงที่ใดในการปรับแต่งนี้ชีวิต (จงใจเลือกมากกว่าให้รูปแบบ retridge ตัวเองทําความสอดคล้องกันเพราะรูปแบบ matching ภายใน ` <Location> ` บล็อก สามารถ ทํา หน้า ที่ คลุมเครือ — ดู ข้อ ความ ข้าง ล่าง) . ทําลายรีเอ็กซ์

 `^/ serdap/` ต้องเริ่มด้วย / เร็ดแดป/
 (ตารางกริด |  tabledap ) / - ตามด้วยหนึ่งในสองคน ERDDAP™ วิธีการเข้าใช้

 `[^/?] +` - datasetID หนึ่งตัวละครหรือมากกว่าที่ไม่ใช่ / หรือ?

 `/` — จุด ตาม ตัว อักษร

 ` (? &#33; (ครัวซองต์ | ไอโซ19115_2 | ... | ncojsonHader) $) ` -- ดูหัวลบ: "ตราบใดที่สิ่งที่ตามมา ไม่ได้เป็นหนึ่งในไฟล์ที่แน่นอนเหล่านี้ พิมพ์ชื่อไปจนถึงท้ายข้อความ" นี่เป็นรูปแบบแฟ้ม ERDDAP™ สามารถให้บริการอย่างถูกต้องตามกฎหมายโดยไม่มีเงื่อนไข (ข้อมูลกํากับภาพ โครงสร้าง แบบฟอร์ม เป็นต้น) -ไอ้หน้าหล่อนั่น มันกันพวกมันไม่ให้ถูกบล็อก

 `[A-Za-z0-9_]+$` -ไฟล์จริง ส่วนขยายแฟ้ม (ตัวอักษร, ตัวเลข, เน้น) ต้องวิ่งไปที่ปลายสาย
เงื่อนไขนี้เป็นจริงเฉพาะเมื่อเส้นทางเป็นตาราง dap/ tabledap ต้องการบางแฟ้ม ประเภทที่ไม่ได้อยู่ใน รายชื่อปลอดภัยโดยไม่มีการใช้

สาย 4 — `เขียน Rule ^ - [R=429, L]` 
กฎของมันเอง เพราะเงื่อนไขทั้งสองข้างข้างต้นต้องเป็นจริงอยู่แล้ว สําหรับอาปาเช่ที่จะคํานวณเส้นตรงนี้ รูปแบบตรงนี้ไม่จําเป็นต้องตรวจสอบสิ่งอื่น - หมายความว่า "อย่าเปลี่ยนชื่อที่อยู่ URL ใหม่ (เราจะไม่เปลี่ยนเส้นทางไปไหน แค่ขอสั้นๆ) . ธง:

 `R=429` ตอบสนองด้วยการกระทํา HTTP-HTTP-คลาสที่มีรหัสสถานะ 429 ("ขอมากมาย") แทนที่จะทําตามคําขอ
L — "Last": หยุดประมวลผลกฎเพิ่มเติมเพิ่มเติมใด ๆ เมื่อไฟนี้
ใส่ร่วมกัน: หากข้อความร้องขอว่าง และการร้องขอเป็นตารางdap / tabledap แฟ้ม ชนิดที่ไม่ได้อยู่ในรายการที่ไม่ได้รับการฝึกอบรมความปลอดภัย กลับมาทันที 429 — โดยไม่ต้องติดต่อ ERDDAP แบ็คเก็ตทอมแคท

ทําไม `% &#123;1&#125;` แทนที่จะให้รูปแบบการเขียนใหม่ตรงกับพาธโดยตรง (คุ้มค่าที่จะรวมเป็นโน้ตสําหรับเพื่อนร่วมงาน เนื่องจากมันเป็นส่วนที่ไม่น่ารังเกียจ) ภายใน ` <Location> ` บล็อก สิ่งที่รูปแบบการเขียน Roule แบบเปลือยนั้น เข้ากันได้กับพฤติกรรม การดึงข้อมูลพาธเต็มโดยใช้ชื่อเดิม `% &#123;1&#125;` ขั้นตอนที่คลุมเครือโดยสิ้นเชิง -- มันเป็นเส้นทางตามจริงเสมอ การเรียกร้องที่สมบูรณ์ ดังนั้นรีเรกซ์ประพฤติตรงตามที่เขียน


ผม ใช้ วิธี นี้ มา หลาย วัน แล้ว และ ดู เหมือน จะ ใช้ ได้ ผล ดี มาก มัน ขัด ขวาง สิ่ง ที่ ผม พยายาม ขัด ขวาง และ ไม่ ขัด ขวาง สิ่ง ที่ ผม ไม่ ต้องการ ขัด ขวาง. และ ERDDAP™ ได้มีความเสถียรมากขึ้น
