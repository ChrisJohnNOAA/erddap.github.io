## ソリューション

「私は見つけた」というソリューションは、Apache2で機能します。私はnginxを知らないが、私は同様のことを想像しています。 最初はmod_security を試しましたが、複雑すぎてとてもうまくいませんでした。 mod_rewrite を使う。 今、私は何かですが、この専門家です, 私は私が達成しようとしていたものを定義しながら、, ソリューション, だけでなく、説明, クロードによるものです. アイ。 ChatGPTは、基本的に同じ回答を提供します。

ステップ1。 mod_rewriteがインストールされ、有効になっていることを確認してください。 これを行う方法は、OSと異なるので、これはあなたのお気に入りのチャットボットを尋ねることができるものです。

ステップ2。 apache2用のslを構成する適切なファイルで (OSによって再び変化する) たとえば、/etc/apache2/sites-enabled/ssl.conf のようなものになるかもしれません。適切な VirtualHost 定義で以下を追加します。 (これをコピーすると4行しかない場合は、3行目はラップし、それを解除することができます。) 

```
RewriteEngine On
RewriteCond %{QUERY_STRING} ^$
RewriteCond %{REQUEST_URI} ^/erddap/(griddap|tabledap)/[^/?]+\\.(?!(?:croissant|iso19115_2|iso19139_2007|iso19115_3_2016|ncCFHeader|ncCFMAHeader|das|dds|html|graph|subset|ncHeader|help|fgdc|iso19115|ncoJsonHeader)$)[A-Za-z0-9_]+$
RewriteRule ^ - [R=429,L]
```

ステップ3。 設定が有効であることを確認してください: `sudo apache2ctl 設定テスト` 

ステップステップ 4. apache2を再起動して下さい: `sudo systemctl 再起動 apache2` 

ステップ5. 何もブロックされていないログをチェックし、その制約のない適切なリクエストは、Tomcat を打つことなく 429 を返す

## 導入事例

なぜこの作業とこれを行うのか - ここではClaude.aiの説明です:

ライン1 — `リライトエンジン お問い合わせ` 
このスコープの mod_rewrite 処理をオンにします。 それなしで、RewriteCond/RewriteRule ディレクティブは単に無視されます。

ライン2 — `リライトコンド %&#123;QUERY_STRING&#125; ^$` 
ルールが適用される前に真でなければなりません。 `%&#123;QUERY_STRING&#125; は、` 結局のところ? URL リクエストで。 ^$ は "文字列の開始直後に続く" という正規表現です。つまり、空の文字列です。 そのため、この条件は、クエリ文字列がまったくない場合にのみ当てはまります。リクエストのサブセット/コンストラント式はありません。

ライン3 — `リライトコンド %&#123;REQUEST_URI&#125; ^/erddap/ (グリッドダップ |  tabledap ) /[^/?]+\\。 (お問い合わせ (?:...) ドル) [A-Za-z0-9_]+$` 
2番目の条件、逆にチェック `%&#123;REQUEST_URI&#125;の一覧` — クライアントが送信したリテラルリクエストパスは、コンフィグのこのルールがどこに住んでいるかにかかわらず、常に完全なパス (RewriteRule パターン自体が一致するので、RewriteRule パターンを内部にマッチさせるようにするために意図的に選択した ` <Location> ` ブロックは曖昧に振る舞うことができます — 以下に注意してください) お問い合わせ regexを破壊する:

 `^/erddap/` — /erddap/ で起動する必要があります。
 (グリッドダップ |  tabledap ) / — 続いて 2 つ ERDDAP™ アクセス方法

 `[^/?]+` — と datasetID : / または ?

 `お問い合わせ` — リテラルドット

 ` (お問い合わせ (?:クロワッサン | イソ19115_2 | ・・・ | ncoJson ヘッダー) ドル) ` — ネガティブなルカヘッド: 「以下がこれらの正確なファイルの1つではない限り 文字列の末尾のすべての方法の名前を入力します。 これらは fileTypes です ERDDAP™ 制約なしで正当にサービスを提供できます (メタデータ、構造、フォームページなど) — lookahead はブロックされているから除外するものです。

 `[A-Za-z0-9_]+$` — 実際のファイル タイプ 延長 (文字、数字、アンダースコア) 文字列の最後に実行する必要があります。
そのため、この条件は、パスがグリッドダップ/ tabledap ファイルのリクエスト 安全でないリストにないタイプ。

ライン4 — `リライトルール ^ - [R=429,L]` 
ルール自体。 上記の両方の条件は、Apache がこの行を評価するために既に真でなければなりませんので、ここでパターンは他のものをチェックする必要はありません。 ^ は、常に真の「文字列の開始」と一致します。 - "URLを別のものに書き換えないでください" (リクエストを短絡するだけで、どこにでもリダイレクトしません。) お問い合わせ フラグ:

 `R=429の特長` — ステータスコード429を運ぶHTTPリダイレクトクラスアクションで対応 (「too 多くのリクエスト」) リクエストの代わりに。
L — "Last": この1つの火災が起きると、さらに再書き込みルールの処理を停止します。
まとめる: クエリ文字列が空の場合、リクエストは Griddap/ tabledap ファイル 安全でないリストにないタイプ、すぐに429を返します。 ERDDAP /Tomcat バックエンド。

なぜ? `%&#123;REQUEST_URI&#125;の一覧` RewriteRule パターンを直接パスにマッチさせる代わりに (同僚のメモとして価値がある、それは非従順な部分だから) : 内側 ` <Location> ` ブロックは、RewriteRule パターンが実際にマッチしているのは、Apache バージョンとコンテキストに依存して意図的に動作するものです。 RewriteCond を介してフルパスを明示的に引き出す `%&#123;REQUEST_URI&#125;の一覧` 完全に曖昧さの面ステップ — それは、常に文字通り、完全なリクエストパスなので、正規表現は規則がネストされた場所に関係なく、正確に書かれているように振る舞います。
